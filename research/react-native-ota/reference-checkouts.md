## Source-level caveat: OTAShip rollout cache

The inspected CheckForUpdates path first looks up a manifest cache keyed by project, platform, runtime and channel. On a hit it sends the manifest and returns. Only a cache miss reaches rollout eligibility. A qualifying device can therefore appear to populate a response shared with a nonqualifying device. This follows visible control flow; it was not reproduced against a running server and is not a claim about deployed versions.

An OtaKit acceptance test should publish a partial rollout, request from an eligible installation to warm caches, then request from an ineligible installation on the same lane. Repeat across replicas and after rollout-percentage changes. Separately verify that receiving a manifest without fetching assets does not count as a completed delivery.

## Recovery contracts differ

Historical CodePush tracks whether a pending package began loading and was subsequently confirmed. In this Hot Updater iOS revision, native first-content handling marks launch completion; notifyAppReady reads the resulting report. Expo has its own native recovery pipeline. An OtaKit wrapper should expose truthful observations instead of translating these into an identical readiness guarantee.
