# RN implementation status

Date: 2026-09-12. Branch: `research/react-native-ota-plan`.

RN delivery is partially implemented and remains gated. Production has not been migrated or deployed. Both new migrations have been tested and applied only to the disposable local PostgreSQL database. This document distinguishes working components from release acceptance; a passing server suite does not establish a production-ready updater.

## Implemented

- Shared release service selects behavior from the stored app framework. RN uses platform/runtime/channel locks, PostgreSQL-timed actor-bound preparation intents, durable operation replay, atomic baseline initialization, strictly ordered history, and final-baseline protection. Capacitor retains its existing request-hash bytes, locks, v2 manifest/signature format and native updater.
- RN ZIP/delta initiation and finalization validate full targeting, plaintext content identity, transport identity, inventory and baseline provenance. Ordinary retries require exact agreement and never implicitly adopt a different stored representation. Shared Unicode 15 case-folding/path rules reject aliases, traversal, reserved names and oversized inventories.
- Signed v3 manifests bind app, framework, OS, runtime, channel, version, transport/content hashes, size, encryption, release ID and expiry. Native implementations verify P-256 DER signatures and exact artifact contents.
- Explicit baseline-adoption preparation returns the stored winning representation. The CLI verifier checks the actual archive or delta bytes, inventory, encryption key identity and AES-GCM authentication before recording adoption. It protects an existing incompatible receipt from overwrite. `rn adopt-baseline` now orchestrates ZIP adoption before OTA upload, binding the verified stored representation while preserving the unused local transport. Durable adoption receipts omit download capabilities and tolerate URL rotation.
- `rn prepare-upload` and `rn upload` verify archived build provenance and save both exact ZIP transports before network mutations. Receipts bind server/org/actor/encryption policy. Known sessions resume through an RN-only endpoint without extending their original expiry; lost finalization responses retry the original ID without another PUT. Every retry rechecks archives and transport hashes, encrypted bytes are never regenerated, baseline finalization precedes OTA binding, and publication remains separate. Expired sessions and conflicts require reconciliation rather than silent replacement or adoption.
- Bare RN exporter runs the installed Metro asset mapper, compiles actual Hermes bytecode, composes a private source map, verifies the complete payload and writes immutable export/embedded receipts and ZIP archives. Native-input capture includes installed dependency/autolinking/fingerprint/compiler evidence and rechecks it across export. The transitive native updater-core sources are explicitly included and missing fingerprint evidence is rejected.
- `rn stage-embedded` now prepares the complete native resource folder from a verified archived export and host settings recorded before export. It derives receipt/build/version fields, includes the exact Unicode table, excludes private files, publishes only a complete folder, and verifies identical retries without merging or overwriting changed output. Recorded host settings contribute to runtime identity through file and canonical hashes. Package sealing checks the Unicode table and recorded host settings, including server URLs and keys. Older records retain manual preparation and their prior generated-field checks; staging requires recorded settings. Android APK task registration and opt-in Xcode phase/wrapper integration are implemented.
- `rn export-embedded`, `rn seal-build` and `rn export` distinguish prepared inputs, a verified completed native package and an OTA export. Sealing verifies the actual APK/iOS app identity, complete embedded payload, receipt and host configuration against the archived baseline, pins the package hash and prevents receipt replacement. OTA export requires that completed receipt and preserves the original baseline privately instead of inventing a new embedded baseline. Native input collection runs outside global Node search paths so package-manager launchers cannot introduce unrelated Expo packages; Hermes is resolved from RN's installed dependency. Complete resolved-input collection remains outstanding; this is local CI package provenance, not store/signature attestation. See the [build workflow](../../packages/cli/src/lib/react-native/README.md).
- The optional shipped `scripts/android.gradle` hook registers generated assets and APK sealing for explicitly selected non-debuggable Hermes variants. It exports/stages before asset merging, archives and seals one APK before assemble/install, and retains separate build archives. Resolved external runtime artifacts, Android boot classpath, hook source and evaluated Android variant settings enter native evidence. Unsupported RN bundler/compiler overrides are rejected. Failed packaging cannot trigger sealing through a finalizer. Other variants keep their existing bundling behavior. Split APKs, AABs, configuration-cache/build-cache reuse and the complete custom native-input closure remain unaccepted.
- `rn build-ios` and the shipped `scripts/xcode.sh` hook export/stage inside the selected app’s RN phase, then archive and seal the `.app` only after Xcode succeeds, including its later signing phases. Fresh requests bind actual target/configuration/settings and native inputs; skipped, stale and failed invocations cannot produce completed receipts. CocoaPods lock agreement, generated pod configuration, project/workspace, installed hook/environment script, selected Hermes compiler and evaluated native settings contribute evidence. Packaging checks actual app version fields only for the new versioned Xcode record; legacy records retain their existing checks. The workflow uses separate private archives and leaves ordinary RN bundling available outside the explicit opt-in. `.xcarchive`/IPA orchestration, signing acceptance, arbitrary custom native input closure and Expo integration remain outstanding.
- Native fingerprinting now excludes generated Android `.kotlin` compiler caches, matching their existing exclusion from supplemental source hashing. A real isolated Gradle build exposed an upstream fingerprint of a temporary `.salive` session marker that vanished at Gradle exit; this made a later OTA export reject an otherwise unchanged build. The exclusion retains native source/configuration evidence and prevents that transient file from defining compatibility.
- `otakit rn prepare-publication` and `otakit rn publish` save an actor/org/server-bound, locked, durable local receipt before sending a mutation. A lost response retries the original operation key and intent; it does not silently prepare a new publication. `rn prepare-collection` now preflights every selected uploaded variant under one display version before writing a collection receipt; `rn publish-collection` validates all replay scopes/windows before sending, preserves independent commits and uncertain operations, and resumes without resending completed targets or preparing replacement intents. Collection upload orchestration remains outstanding.
- RN dashboard rows distinguish platform/runtime variants sharing a version. Publish/revert use prepared intents and persist retry receipts. API/CLI/MCP listing supports optional RN platform/runtime filters; Capacitor preserves its existing list behavior. Baseline deletion conflicts return a typed error before object deletion.
- Expansion migration `20260911120000_rn_delivery_expand` and final constraint migration `20260911180000_rn_target_uniqueness` preserve legacy rows and backfill targeting. The final migration allows RN platform/runtime variants of one version, retains Capacitor version uniqueness with a partial index, and adds RN target checks. The Prisma schema matches the migrated local database.
- Swift core and iOS RN host support signed ZIP/delta installation, AES-GCM, durable verified cache receipts, offline cold-launch verification, generation-scoped readiness/activation, foreground-only timeout, rollback, quarantine and a durable event outbox. Downloads are bounded and reject redirects.
- Java core implements equivalent signature/archive/inventory/cache verification and durable launch recovery. Android host/module integration compiles in Debug and Release. Release emulator acceptance passed on API 24 and API 36, including actual RN headless-task activation deferral. P-256 key validation uses exact curve parameters without requiring an EC AlgorithmParameters provider unavailable on API 24.
- Both native hosts schedule cache collection after durable cold recovery, independently of RN startup and serialized with downloads. Current, last-good, previous confirmed and staged artifacts keep their receipts. Unreferenced artifacts and interrupted staging are removed without following symbolic links; Android also removes owned partial downloads. The optional `previousGood` pointer preserves the prior confirmed artifact without changing rollback selection or invalidating older saved states. Cleanup failures leave launch state intact and retry at a future cold start. This bounds retained code across cold starts, not downloads in an indefinitely running process.
- Android exposes additive preparation, dynamic bundle-selection and host-attachment hooks. The bare delegate uses the same extracted selection/listener logic. A private Expo local module now preserves Expo's factory and defers its surface through the installed SDK's handlers; real Application Activity callbacks preserve foreground observations during preparation. The Activity handler must read release flags only in `getDelayLoadAppHandler`: Expo constructs its handler list before Android attaches the Activity Context. An emulator launch caught that ordering issue and the later callback fixes it. Debug host selection remains Expo-owned, and Metro has an explicit disabled option without changing its enabled default.
- Metro bootstrap and Expo constants/DOM facades exist. The Expo 57.0.17 / CLI 57.0.19 adapter now consumes the native embed export and validates its full native asset mapping before copying. It preserves a public config snapshot and DOM HTML/JS/assets, keeping native and DOM maps private. Explicit supplemental hashes cover generated native projects and pnpm native dependencies skipped by upstream fingerprint rules; unknown missing evidence still fails. iOS and Android archive acceptance pass with an independent Expo/DOM entry. Full Router export is blocked by conflicting icon scale files in Router 57.0.17 and the checked 57.0.21 archive. Expo config-plugin/native host/device acceptance remains incomplete.
- Expo native-input capture and export now initialize production mode and load the installed Expo CLI’s production environment before config, fingerprinting or Metro evaluation. Conflicting `NODE_ENV`/`BABEL_ENV` values fail before export. Environment files contribute hashes, and changes invalidate the selected build evidence; receipts record those hashes rather than copying dotenv file contents. The adapter resets Metro transforms because repeated SDK 57 exports reproduced stale inlined public environment values alongside a newer config snapshot. CLI internals resolve through Expo’s own dependency, matching `expo/bin/cli`, without requiring a direct application CLI dependency. Bare RN does not enter this setup.
- Both native hosts deliver the existing event envelope asynchronously when `ingestURL` is configured. The state transaction records verified download/staging, readiness success, attributed download failure and trial rollback. Retries preserve UUIDs and timestamps; only HTTP 202 acknowledges. Backoff, 256-event/24-hour retention, terminal-error/drop diagnostics, redirect rejection and bounded response handling are implemented. Malformed outbox entries preserve healthy launch pointers. Confirmed-content association changes neither the executing JS context nor old events, and a real embedded baseline switch now retains the outgoing fallback until readiness.
- Native npm archives now contain explicit source inventories and MIT licenses, excluding build output, fixture keys, tests and source maps. The iOS CocoaPods helper resolves the exact installed native-core dependency instead of a repository-relative Podfile path. Isolated pnpm installation, RN autolinking, CocoaPods resolution and both Release native builds passed using actual tarballs outside the workspace. The packages remain private and unpublished.

Capacitor runtime reads still join the bundle to tolerate mixed old/new writers. Switching all Capacitor reads to indexed release snapshots requires an explicit writer-drain cutover. RN creation remains disabled. Do not deploy the final constraint migration while older writers still depend on global version uniqueness.

## Reproduce local checks

Use a disposable local database only:

```sh
export DATABASE_URL='postgresql://otakit_test@127.0.0.1:55432/otakit_rn_test?schema=public'
pnpm --filter @otakit/console db:generate
pnpm --filter @otakit/console db:migrate
RUN_DATABASE_TESTS=1 pnpm test
pnpm typecheck
pnpm --filter @otakit/cli build
RUN_RN_EXPORT_TESTS=1 pnpm --filter @otakit/cli test -- src/lib/react-native/export.integration.test.ts
RUN_DATABASE_TESTS=1 RUN_RN_UPLOAD_CLI_TESTS=1 RN_OTA_EXPORT="$OTAKIT_OTA_DIR" \
  pnpm --filter @otakit/console test -- lib/services/rn-uploads.integration.test.ts
```

See `examples/react-native-app/README.md` for native fixture requirements and execution.

With local Android/JDK environment variables configured, run the hook acceptance using native inputs that record their host settings file:

```sh
RUN_RN_GRADLE_TESTS=1 RN_GRADLE_NATIVE_INPUTS="$OTAKIT_NATIVE_INPUTS" \
  pnpm --filter @otakit/cli test -- src/lib/react-native/android-build.integration.test.ts
```

This invokes real fixture Gradle builds, checks archive retention and post-build OTA export, and deliberately fails a packaging task. It leaves successful archives under the fixture's `android/app/build/otakit/release/` directory.

With Xcode and an available iOS simulator, exercise the workspace hook using a dedicated DerivedData directory:

```sh
RUN_RN_XCODE_TESTS=1 RN_XCODE_NATIVE_INPUTS="$OTAKIT_IOS_NATIVE_INPUTS" \
  RN_XCODE_DERIVED_DATA=/private/tmp/otakit-fixture-derived-data \
  RN_XCODE_DESTINATION='platform=iOS Simulator,id=<UDID>' \
  pnpm --filter @otakit/cli test -- src/lib/react-native/ios-build.integration.test.ts
```

This builds two archived apps, exports OTA, simulates failure after a real native build, rejects a skipped invocation, then checks ordinary fixture bundling. It uses a local simulator SDK with signing explicitly disabled and retains private test archives in the system temporary directory.
